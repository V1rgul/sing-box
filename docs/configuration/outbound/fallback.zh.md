!!! question "自 sing-box 1.15.0 起"

### 结构

```json
{
  "type": "fallback",
  "tag": "fallback",

  "outbounds": [
    "wireguard",
    "openvpn"
  ],
  "timeout": "",
  "interrupt_exist_connections": false
}
```

### 字段

#### outbounds

==必填==

按优先顺序排列的出站标签列表。

选择第一个已连接的出站。尚未连接的出站会在 `timeout` 内占用选择权，直到其连接成功、失败或超时，在此之前不会考虑排在其后的出站。当排在前面的出站重新连接时，立即切换回该出站。如果没有已连接的出站，则选择第一个出站。

TCP 和 UDP 使用同一个选定的出站。

#### timeout

回退到下一个出站之前等待出站连接的时间，以及已连接的出站断开后等待其重新连接的时间。默认使用 `10s`。

WireGuard 在上一次握手发起消息 5 秒后（另加最多 333 毫秒）重传握手发起消息，因此默认值允许一次重传。

未连接的出站会被依次等待，因此存在多个未连接的出站时，回退可能需要数倍于 `timeout` 的时间。当 `fallback` 出站组被用作另一个出站组的出站时，外层出站组的 `timeout` 应不短于内层出站组完成回退所需的时间。

报告终止错误的出站将被直接跳过，不会等待。

当设备暂停或网络不可用时，不会进行回退，之后将重新等待未连接的出站。

#### interrupt_exist_connections

切换回靠前的出站时，中断此前选定出站的现有连接。

切换离开未连接的出站时，该出站上的现有连接将始终被中断。

仅入站连接受此设置影响，内部连接将始终被中断。

### 连接状态

此出站组不进行 URL 测试，而是使用各出站自身报告的连接状态。

| 类型               | 已连接的条件                                                       |
|------------------|--------------------------------------------------------------|
| `wireguard`      | 每个设置了 `address` 的对等方均有已建立的会话（已完成且未过期的握手）。没有此类对等方的 WireGuard 端点始终视为已连接。 |
| `openvpn-client` | 隧道已建立并完成配置。等待认证质询应答期间视为未连接。终止错误（例如 `auth_retry` 为 `none` 时的认证失败）将报告为失败。 |
| `openconnect`    | 隧道已建立并完成配置。终止错误将报告为失败。                                        |
| `fallback`       | 其选定的出站已连接。当其所有出站均失败时报告为失败。                                    |

其他出站（包括 `selector` 与 `urltest` 出站组）没有连接状态，始终视为已连接，因此排在此类出站之后的出站永远不会被使用。此类出站（例如 `direct`）放在最后时，可用作兜底出站：在其之前的所有出站均不可用时由它承载流量。如果流量绝不能绕过隧道，请勿添加此类出站。

出站组会使选定的出站及其之前的出站保持连接；如果没有已连接的出站，则所有出站都会保持连接尝试。此时 WireGuard 端点会自行发起握手（即使没有流量），并在网络变化后强制进行新的握手，以使其状态反映新的网络路径。在出站组等待切换回 WireGuard 端点期间，该端点会持续重试握手，与设置了 `persistent_keepalive_interval` 时的行为相同。有出站已连接时，其后的出站不会被使用，其中的按需端点将被挂起（参阅 [WireGuard](/zh/configuration/endpoint/wireguard/#on_demand)、[OpenVPN](/zh/configuration/endpoint/openvpn-client/#on_demand) 与 [OpenConnect](/zh/configuration/endpoint/openconnect/#on_demand) 的 `on_demand`）。

被用作另一个出站组的出站时，`fallback` 出站组即使未被外层出站组选定，也会使其自身的第一个出站保持连接。

!!! note ""

    WireGuard 握手未完成仅表示未收到经过认证的响应：服务器可能不可达、UDP 可能被过滤，或密钥可能不匹配。

!!! warning ""

    在没有网络变化的情况下，静默失效的 WireGuard 会话只有在 WireGuard 使其过期时才会被检测到，即最后一次握手后最多 3 分钟。
